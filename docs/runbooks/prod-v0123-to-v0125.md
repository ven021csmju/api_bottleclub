- ห้าม echo, วาง หรือส่ง secret เป็น argument
- ห้าม push ขึ้น GitHub จากขั้นตอนนี้ (push แยกเป็นงานของเจ้าของ)
- ฉบับนี้ใช้แทน `phase49-deploy.md` ข้อ 3–4 และ `phase50-deploy.md` ข้อ 1–3 สำหรับการข้ามจาก v0.1.23 ไป v0.1.25 รวดเดียว ไม่ต้อง deploy v0.1.24 ก่อน

## 2. Backup ครั้งเดียวก่อนเริ่ม (ห้ามข้าม)

```bash
cd ~/api_bottleclub
sudo scripts/ops/prod_db.sh backup pre-v0125
#   prod_db: OK /var/backups/bottleclub/pg/bottleclub_prod-pre-v0125-<stamp>.dump <size>; entries: N, table data: M
sudo /usr/lib/postgresql/16/bin/pg_restore --list /var/backups/bottleclub/pg/bottleclub_prod-pre-v0125-*.dump | grep -c 'TABLE DATA'   # = M
sudo systemctl start bottleclub-backup.service && journalctl -u bottleclub-backup -n 5 --no-pager   # สำเนา off-site (B2)
```

**ตรวจ:** มีบรรทัด `OK` และ `table data` สองครั้งตรงกัน ถ้าไม่ตรงให้หยุด เก็บไฟล์ dump นี้ไว้จนกว่าจะไม่ต้องย้อน v0.1.25 แล้ว

## 4. Migration 022 → 026 และ GRANT (ก่อน code)

```bash
M=/opt/bottleclub/releases/<sha12>/migrations
for m in 022_order_shipping_carrier 023_customer_line_login 024_service_keys 025_service_key_scope_lookup 026_products_demo_online; do
  sudo ~/api_bottleclub/scripts/ops/prod_db.sh apply $M/$m.sql || break; done
```

NOTICE ที่ต้องเห็น (ตามลำดับ):
- `022: orders.shipping_carrier`
- `023: customer_accounts, customer_identities, auth_exchange_codes`
- `024: service_keys`
- `025: 0 service key(s) with customers.read revoked`
- `026: products.is_demo, products.is_online, ck_products_demo_sku; 0 DEMO- row(s) marked`

แต่ละไฟล์อยู่ใน transaction ของตัวเอง ไฟล์ที่ error จะไม่มีผล และ loop หยุดทันที ถ้าหยุดกลางทาง: แก้สาเหตุแล้วรัน loop เดิมซ้ำได้ ไฟล์ที่ทำไปแล้วจะตอบ `already applied`

```bash
sudo ~/api_bottleclub/scripts/ops/prod_db.sh apply ~/api_bottleclub/scripts/ops/phase49_grants.sql
# ต้องจบด้วย "phase49_grants: OK, every privilege held"
cd /tmp && sudo -u postgres psql -p 5433 -d bottleclub_prod -XAt -c \
  "SELECT string_agg(version, ',' ORDER BY version) FROM schema_migrations WHERE version >= '022'"   # 022,023,024,025,026
```

- GRANT ครอบตารางใหม่ของ 023/024 ส่วน 026 ไม่มีตารางใหม่ (role ของ API มี DML บน `products` อยู่แล้ว)
- **จุดหยุดที่ปลอดภัย:** v0.1.23 ยังทำงานต่อบน schema นี้ได้ (ข้อ 8.1)

## 5. Env ของ Phase 49 + 50

ค่าเริ่มต้นของ v0.1.25: catalog ปิดทุก environment (ไม่อนุมานจาก `ENVIRONMENT` แล้ว) แต่ให้เขียนค่าไว้ชัดๆ ใน `api.env` เพื่อให้อ่านไฟล์แล้วรู้สถานะ

| Env | ไฟล์ | ค่ารอบนี้ | หมายเหตุ |
|---|---|---|---|
| `STOREFRONT_CATALOG_ENABLED` | `api.env` | `false` | เปิดหลังที่ปรึกษากฎหมายยืนยันเท่านั้น |
| `REGISTRATION_ENABLED` | `api.env` | `false` | เดิมไม่ได้ตั้ง (ปิดเพราะ `ENVIRONMENT=production`) ตั้งให้ชัด ไม่ให้ขึ้นกับ `ENVIRONMENT` |
| `CUSTOMER_JWT_SECRET_KEY` | `secrets.env` | random 64 hex | ไม่ใช่ flag: key ของ token ลูกค้า ตั้งไว้ก่อนได้ (ตอน start API ตรวจว่ายาว ≥ 32 และไม่เท่ากับ `JWT_SECRET_KEY` ถ้าผิดจะ start ไม่ได้ ซึ่งพบที่ข้อ 6 และ tool จะสลับกลับเอง) |
| `LINE_CLIENT_ID`, `LINE_CLIENT_SECRET`, `LINE_REDIRECT_URI`, `LINE_DEFAULT_ORGANIZATION_ID`, `FRONTEND_URLS` | — | **ไม่ตั้ง** | รอ channel production; ไม่ตั้ง = `/auth/line` ตอบ 400 `LINE_NOT_CONFIGURED` |
| `GOOGLE_*` | — | **ไม่ตั้ง** | |
| `STOREFRONT_ORGANIZATION_ID` | — | ไม่ตั้ง | องค์กร active เดียว |
| `RATE_LIMIT_ORDER_TRACK_PUBLIC`, `RATE_LIMIT_SOCIAL_LOGIN`, `RATE_LIMIT_AUTH_EXCHANGE`, `RATE_LIMIT_CUSTOMER_LOOKUP`, `RATE_LIMIT_STOREFRONT_CATALOG`, `CUSTOMER_ACCESS_TOKEN_EXPIRE_MINUTES`, `AUTH_EXCHANGE_CODE_TTL_SECONDS`, `CLOUDFLARE_IP_RANGES(_FILE)` | — | ไม่ตั้ง | ใช้ค่าเริ่มต้น; `TRUSTED_PROXY_IPS` ค่าเดิม (tunnel) |

```bash
sudo cp -p /etc/bottleclub/api.env /etc/bottleclub/api.env.bak-v0123
sudo cp -p /etc/bottleclub/secrets.env /etc/bottleclub/secrets.env.bak-v0123
sudo bash -c 'set -euo pipefail; f=/etc/bottleclub/api.env
  grep -q "^STOREFRONT_CATALOG_ENABLED=" $f || echo "STOREFRONT_CATALOG_ENABLED=false" >> $f
  grep -q "^REGISTRATION_ENABLED=" $f || echo "REGISTRATION_ENABLED=false" >> $f
  grep -E "^(STOREFRONT_CATALOG_ENABLED|REGISTRATION_ENABLED|LINE_|FRONTEND_URLS|GOOGLE_)" $f'
#   ต้องเห็นแค่ 2 บรรทัด: STOREFRONT_CATALOG_ENABLED=false และ REGISTRATION_ENABLED=false
sudo bash -c 'set -euo pipefail; umask 077; f=/etc/bottleclub/secrets.env
  grep -q "^CUSTOMER_JWT_SECRET_KEY=" $f || printf "CUSTOMER_JWT_SECRET_KEY=%s\n" "$(openssl rand -hex 32)" >> $f
  grep -c "^CUSTOMER_JWT_SECRET_KEY=" $f; grep -cE "^(LINE_|GOOGLE_)" $f || true'   # 1 แล้ว 0
# สำเนาที่ไม่มี secret ของ api.env
grep -q "^STOREFRONT_CATALOG_ENABLED=" ~/bottleclub-prod/api.env || printf 'STOREFRONT_CATALOG_ENABLED=false\nREGISTRATION_ENABLED=false\n' >> ~/bottleclub-prod/api.env
```

ไม่ต้อง restart ในขั้นนี้ ข้อ 6 ทำให้เอง

## 6. Deploy code และตรวจหลัง deploy

```bash
sudo bottleclub-deploy v0.1.25
```
- ก่อนถาม `[y/N]` tool ต้องแสดง `every migration in this release is recorded in schema_migrations` ถ้าแสดงรายการที่ขาด ให้ตอบ N แล้วกลับไปข้อ 4
- tool ตรวจ `/health` และ DB probe เอง ถ้าไม่ผ่านจะสลับกลับ v0.1.23 ให้เอง (แล้วข้ามไปข้อ 8.2 แถว env)

ชุดตรวจ (ทุกบรรทัดต้องได้ตามที่เขียน):
```bash

readlink -f /opt/bottleclub/current                                                                   # .../releases/<sha12>
```

**จุดหยุดที่ปลอดภัย:** นี่คือสภาพเป้าหมายของรอบนี้ หยุดตรงนี้ได้นานเท่าไรก็ได้

### 8.4 Restore จาก backup ข้อ 2 (ทางสุดท้าย: ข้อมูลหลัง backup หายทั้งหมด)

```bash
sudo systemctl stop fastapi
cd /tmp && sudo -u postgres createdb -p 5433 -O bottleclub_owner bottleclub_prod_restore
sudo -u postgres /usr/lib/postgresql/16/bin/pg_restore -p 5433 -d bottleclub_prod_restore --exit-on-error \
  /var/backups/bottleclub/pg/bottleclub_prod-pre-v0125-<stamp>.dump
sudo -u postgres psql -p 5433 -d bottleclub_prod_restore -XAt -c "SELECT max(version) FROM schema_migrations"   # 021
sudo -u postgres psql -p 5433 -X -c "ALTER DATABASE bottleclub_prod RENAME TO bottleclub_prod_v0125_failed" \
                                 -c "ALTER DATABASE bottleclub_prod_restore RENAME TO bottleclub_prod"
sudo cp -p /etc/bottleclub/api.env.bak-v0123 /etc/bottleclub/api.env && sudo cp -p /etc/bottleclub/secrets.env.bak-v0123 /etc/bottleclub/secrets.env
sudo bottleclub-deploy v0.1.23
```
